# Day 3 — 2026-09-25

Multi-source evidence retriever. No embedding ranker and no judge.

## Shipped

- Strict `Evidence` model (`id`, `title`, `snippet` for the abstract or a
  short snippet, `source` of `openalex` / `arxiv` / `semantic_scholar`,
  optional `work_id`, `doi`, and `arxiv_id`, `url`, optional `score`). Extra
  fields are rejected.
- `retrieve_evidence` queries OpenAlex (primary, existing works client and
  disk cache), the arXiv Atom API (no key), and the Semantic Scholar Graph
  API. Semantic Scholar stays unauthenticated unless `CLAIMFORGE_S2_API_KEY`
  is set. That variable is optional, is not required in CI, and is not a
  secret in the repo.
- Semantic Scholar HTTP 401, 403, and 429 return an empty contribution. If
  one catalog fails, the others are still returned. The CLI exits 1 only when
  every source fails.
- Duplicate works merge on DOI or arXiv id. The pack keeps the longer snippet
  and a lexical overlap score. `claimforge retrieve-evidence --text "..."` or
  `--claim-json path` prints Evidence JSON.
- Unit tests mock HTTP for each provider. One live retrieval test soft-skips
  on network errors and HTTP 401/429/5xx.

  tests passed on this run: OpenAlex smoke, OpenAlex extract, and evidence
  retrieval. Retrieval did not need every catalog to answer.
- Live `claimforge retrieve-evidence --text "Physics-informed neural networks reduce the error on the Burgers equation." --per-source 2 --top-k 3`
  exited 0 and printed three evidence records from Semantic Scholar and

# Day 4 — 2026-09-25

Ranking and top-k packing. America/New_York date for this note. No judge.

## Shipped

- `claimforge.rank` re-scores a deduplicated evidence pack and keeps top-k
  for the future judge. `score` is cosine similarity clipped to `[0, 1]`.
- Embedding ranker: local sentence-transformers model, default
  `all-MiniLM-L6-v2`. Vectors are JSON files under
  `data/cache/embeddings/<model>/`, keyed by the SHA-256 of the model name
  and the text. Optional extra: `pip install -e ".[embeddings]"`.
  `CLAIMFORGE_EMBEDDING_MODEL` overrides the model name. Not a secret.
- Lexical ranker: pack-local TF-IDF cosine. Title text is repeated so a
  title hit outweighs a snippet hit. This is the CI path. CI installs
  `.[dev]` only and does not download a model or use a GPU.
- `auto` (the `retrieve_evidence` and CLI default) uses embeddings when
  `sentence-transformers` imports, otherwise TF-IDF. `--ranker lexical` and
  `--ranker embeddings` force one path. A missing extra fails before any
  catalog request.
- `claimforge retrieve-evidence` prints the ranker's `score` on each JSON
  record. Stderr is `ranker: lexical` or `ranker: embeddings`.
- arXiv requests now send
  `User-Agent: ClaimForge/0.1 (mailto:github.com/shehbaz0101/claimforge)` and
  `Accept: application/atom+xml`. A unit test asserts both headers on the
  search call and again on the bytes `CachedHttpClient` sends. HTTP 406 is
  still a soft failure: the other catalogs are kept.

## Failed

- `pytest -m "not integration"` passed: 133 tests, 1 skipped. The skip is
  `test_minilm_ranks_a_related_sentence_higher`, because
  sentence-transformers is not installed. That is the intended CI path.
- A live arXiv search for `electron` (`max_results=1`) with the new headers
  returned one paper, "The electronic structure of cuprates from high energy
  spectroscopy". The Day 3 cache-miss HTTP 406 did not reproduce on this
  call. If arXiv blocks again, retrieval still keeps the other sources.
- `pytest -m integration` passed all three live checks (OpenAlex smoke,
  OpenAlex extract, evidence retrieval). Retrieval used `--ranker lexical`
  in that test, so it did not download an embedding model. CI does not run
  this marker. No secret is committed.

# Day 5 — 2026-09-26

Judge rubric and verdict engine. No eval harness and no evidence store.

## Shipped

- Strict `Verdict` model (`claim_id`, `label` of `support` / `refute` /
  `insufficient`, `confidence` in `[0, 1]`, a short `rationale`,
  `evidence_ids`, and `rubric_scores`). A rubric value may be null. Extra
  fields are rejected.
- Deterministic `judge_claim(claim, evidence)`. `relevance` is the average
  of the max and the mean ranker score. `coverage` rises with non-empty
  snippets and distinct catalogs. `stance_lexical` is signed cue overlap
  in `[-1, 1]` (support and refute phrases, plus a few directional verbs).
  Support needs high relevance, high coverage, and a support lean. Refute
  needs a refute lean and adequate relevance. Otherwise the label is
  insufficient. No model and no network on this path.
- Optional LLM judge behind the same `CLAIMFORGE_LLM_API_KEY` and
  `CLAIMFORGE_LLM_MODEL` gate as extraction. If either is unset, or
  `CLAIMFORGE_LLM_PROVIDER=rules`, the rubric runs. A failed call falls
  back to the rubric. No secret is committed.
- `claimforge verify --text "..."` retrieves with the Day 3/4 client and
  prints a verdict as JSON. `claimforge judge --claim-json ... --evidence-json ...`
  scores a saved pack offline.
- Unit tests cover support, refute, and insufficient packs, the optional
  LLM gate, and both commands. They do not touch the network.

## Failed

- Nothing in the Day 5 scope failed its offline check. `pytest -m "not
  integration"` passed: 185 tests, 1 skipped. The skip is the Day 4 MiniLM
  test, because sentence-transformers is not installed. No model download
  and no `CLAIMFORGE_LLM_*`. The live integration tests were not required
  for this day and were not used as a gate.
- The stance heuristic misses paraphrases that do not share claim terms or
  a listed cue. A high ranker score with no cue stays insufficient. That is
  the rule, not a failed run.
- No API key was set. The LLM branch was tested with a fake chat client.
